# RES construction roadmap

Each phase extends the same deployable estate and ends with business acceptance plus authoritative semantic evidence where an LPAR is available.

| Phase | Coherent increment | Exit condition before expansion |
|---|---|---|
| 0 | LPAR discovery, naming calibration, base libraries, evidence loop | fingerprint reviewed; first cases authoritative |
| A | Foundation configuration, calendar/date, IDs, messages, common ILE services, audit | shared contracts and build DAG proven |
| B | Customer and account master with DDS/native I/O and core SQL views | onboarding/inquiry workflow restartable and secured |
| C | Payment posting plus accounting gateway, journals, commitment and outbox | balanced, reversible, reconciled payment workflow |
| D | Initial 5250 menu, customer/account/payment screens and subfiles | interactive workflow with messages and authorities |
| E | Batch run control and EOD topology with JOBQ/JOBD/SBSD | submitted graph, checkpoints, logs and recovery proven |
| F | DTAQ workers, MSGF/MSGQ/operator inquiry and exception handling | async duplicates/timeouts/MSGW recover safely |
| G | Statements/invoices/operational reports, PRTF/spool/OUTQ/archive | delivery and rerun reconciliation proven |
| H | security administration, AUTL/groups/adopted authority/SoD | allow and deny evidence reviewed independently |
| I | documents and integration contracts: IFS, MQ, web, transfer, socket, mail, DB | deterministic simulators and failure paths proven |
| J | orders, inventory and billing | order-to-cash and stock reconciliation coherent |
| K | bounded trading, settlement, position and high-volume close | finance workload remains optional to core estate |
| L | COBOL/C/C++/Java/REXX/QShell/PASE and controlled older generations | every language has a natural maintained component |
| M | concurrency, failure, recovery and cross-feature interaction expansion | controlled matrices produce reproducible evidence |
| N | historical/obscure capability allocation and semantic edges | every in-scope taxonomy item has honest placement |

Scale is achieved by deepening workflows, data volumes and interactions after feedback—not generating arbitrary programs. No phase starts automatically from this blueprint.
