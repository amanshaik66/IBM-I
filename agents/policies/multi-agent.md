# Concurrent contribution policy

The assignment service owns semantic-ID claims and dependency readiness. Every worker uses a dedicated branch/worktree and one task contract. Shared schema/architecture changes use separately reviewed governance tasks. Merge gates reject duplicate IDs, broken references, out-of-scope paths, and non-evidenced verification. A future execution scheduler grants unique IBM i library/IFS leases, enforces per-environment limits, serializes incompatible cases, records cleanup, and never exposes credentials to task artifacts.
